# Пакет материалов LogicKernel для бэкенд-разработчика

В этой папке 11 курсов, 660 уроков с практикой, описания 6 отдельных задач, готовые JSON-ответы и схемы HTTP API. Её можно использовать отдельно от фронтенда.

**Решения проверяет отдельное ядро.** Бэкенд отдаёт материалы, принимает и сохраняет попытку, передаёт её ядру, затем сохраняет результат и возвращает фронтенду. Способ передачи между бэкендом и ядром определяется отдельно. В этом пакете нет подключённого ядра, аккаунтов и постоянного хранилища попыток.

Начни с [полного руководства BACKEND.md](BACKEND.md). Оно объясняет, что такое JSON-поле, GET, POST, порт, как импортировать файлы и какие ответы нужны интерфейсу. Пути `backend-package/...` в нём относятся к этой папке. Исходники `config.js`, `api.js`, `lesson-view.js` доступны в полном репозитории, а не в ZIP.

## После распаковки

Открой терминал в этой папке. Нужен Node.js; проверки проекта выполняются на Node 24. npm-зависимости для этих команд не требуются:

```powershell
node validate.mjs
node serve.mjs
```

Валидатор проверит материалы. Сервер останется работать на `127.0.0.1:4180`. Во втором окне:

```powershell
curl.exe -i http://127.0.0.1:4180/api/v1/courses
curl.exe -i http://127.0.0.1:4180/api/v1/lessons/python-01
```

Ожидается 200 и JSON с `data` и `meta`. На отправку решения пример отвечает 503: проверка не подключена. Остановка — Ctrl+C. В отдельном пакете валидатор пропускает сравнение с отсутствующим фронтенд-файлом `content/mock-bundle.js`; это нормально.

## Какие файлы использовать

| Путь | Действие |
| --- | --- |
| `manifest.json` | Читать оглавление, версии, связи адресов с файлами и контрольные суммы. |
| `responses/courses/index.json` | Возвращать целиком на GET `/api/v1/courses`. |
| `responses/courses/<id>.json` | Возвращать на GET `/api/v1/courses/<id>`. |
| `responses/lessons/<id>.json` | Возвращать на GET `/api/v1/lessons/<id>`. |
| `catalog-import.json` | Импортировать все курсы и уроки в БД. Это не ответ списка курсов. |
| `courses/*.json` | Альтернатива общему импорту: по одному курсу. Не создавать дубли из двух представлений. |
| `courses/*.md` | Читать человеку; не передавать вместо JSON API. |
| `task-import.json` | Импортировать публичные данные и версии отдельных задач. |
| `schemas/*.json` | Проверять структуру запросов и ответов. Это правила, не программа проверки решения. |
| `examples/*.json` | Использовать как примеры сообщений. accepted в файле — образец, не настоящий результат. |
| `runtime-profiles.json` | Сверять ID профиля с заданием. Выполнение и проверка относятся к ядру. |
| `fixtures/*.sql` | Учебные данные для SQL-заданий. Не выполнять в БД пользователей приложения. |
| `openapi.json` | Читать контракт вместе с соседней папкой `schemas`. |
| `serve.mjs` | Изучить пример выдачи материалов по HTTP. |
| `validate.mjs`, `validation-report.json` | Запуск проверки пакета и её отчёт. |

Браузеру не передают весь архив. Бэкенд получает материалы при подготовке сервера, а посетитель — только запрошенные JSON-ответы. В обратную сторону файлы ученика приходят текстом в `files[].code` одного POST-запроса.

## Где продолжить

В [BACKEND.md](BACKEND.md): раздел 5 — импорт, 6–7 — материалы API, 8 — передача кода и Markdown, 9 — сохранение попытки, 10 — обязанности бэкенда и ядра, 11–12 — ответы и ошибки, 14 — сессии и размещение, 15 — план реализации.

Уроки 13–60 каждого курса содержат многофайловые работы и отчёты с критериями `review`. Не теряй Markdown при сохранении попытки. Публичный текст ожидаемого результата не заменяет проверку ядра. До публикации материалов нужна редактура; статус указан в manifest.

Для обновления пакета используется `tools/package-backend.ps1` из полного репозитория. В отдельном ZIP инструментов сборки и исходников `content/*.js` нет.
