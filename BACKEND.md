# Разработка бэкенда LogicKernel: с чего начать

Полная инструкция находится в [README.md](README.md). Она объясняет JSON и HTTP с нуля, назначение файлов, импорт, точные запросы и ответы, хранение попыток, авторизацию и подключение интерфейса.

**Схема работы: фронтенд → бэкенд → ядро проверки → бэкенд → фронтенд.** Проверяет решения ядро. Бэкенд принимает и сохраняет данные, связывает результат с попыткой и возвращает его пользователю. Протокол общения с ядром согласуется отдельно и здесь не описывается.

1. Прочитай разделы 1–3 README: термины, сеть, файлы.
2. Выполни раздел 4: запусти `node backend-package/serve.mjs`, получи JSON через curl и подключи интерфейс.
3. По разделам 5–8 реализуй выдачу материалов и разберись с запросами решений. Файлы ученика — строки в JSON, не ZIP-загрузка.
4. По разделам 9–12 реализуй снимки, ключи повтора, статусы, историю и выдачу результатов ядра.
5. По разделам 13–15 выбери HTTP-библиотеку, подключи сессии и проверь API.

Готовый `serve.mjs` отдаёт материалы, но не хранит попытки и не подключён к ядру. Поэтому на отправку он отвечает `503 RUNNER_NOT_CONFIGURED`. Это ожидаемое поведение примера.

Для передачи разработчику: [ZIP-пакет](LogicKernel-backend-package.zip), [инструкция пакета](backend-package/README.md), [полная копия руководства](backend-package/BACKEND.md). Формальный контракт — `backend-package/openapi.json` и `backend-package/schemas`.

После изменения главного README выполни `powershell -File tools/package-backend.ps1`, чтобы обновить копию и архив.
